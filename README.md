# Домашнее задание 4: Hilt + Room поверх проекта из ДЗ №3

### ФИО: Полатинский Артем
### Группа: ПИКД(2)

---

## Выбранный API: Rick and Morty API
Описание: Для проекта был выбран Rick and Morty API. Это RESTful API, которое предоставляет информацию о персонажах мультсериала. В приложении реализовано получение списка героев, поиск по имени и детальный просмотр информации.

## Домашнее задание 5: Автотесты

### Выполнено:
* **Юнит-тестов**: 10
* **Интеграционных тестов**: 8 (3 DAO, 2 Repository, 3 Compose UI)

### Покрытые сценарии:
1. **Юнит-тесты (`MappingTest`, `ListViewModelTest`, `DetailViewModelTest`, `FavoritesViewModelTest`):**
   * Преобразование сетевых DTO моделей в доменные.
   * Преобразование доменных моделей в сущности Room (и обратно).
   * Проверка начального состояния (`Loading`).
   * Успешная загрузка данных и переход в состояние `Success`.
   * Ошибка загрузки данных и переход в состояние `Error`.
   * Обработка пустого результата поиска (переход в состояние `Empty`).
   * Чтение ID персонажа из `SavedStateHandle` во `DetailViewModel`.
   * Переключение состояния «Избранное» во `DetailViewModel`.
   * Маппинг избранных персонажей во `FavoritesViewModel`.
2. **Интеграционные тесты (`CharacterDaoIntegrationTest`, `RickAndMortyRepositoryIntegrationTest`, `ComposeUiIntegrationTest`):**
   * Вставка, удаление и чтение избранного в базе данных Room (in-memory).
   * Совместная работа `RickAndMortyRepository` с базой данных Room и Fake API.
   * Рендеринг списка персонажей в Jetpack Compose при успешной загрузке.
   * Обработка ошибок в UI и клик на кнопку «Retry».
   * Клик по элементу списка и передача ID персонажа в навигацию.
3. **Нетривиальные тесты:**
   * Проверка, что вызов `retry()` действительно повторно запрашивает данные с сервера (проверяется счетчик вызовов фейк-репозитория).
   * Проверка отсутствия дублирования в Room при многократном добавлении в избранное.
   * Проверка, что пустой результат сетевого поиска возвращает именно `Empty` стейт, а не `Success(emptyList())`.
4. **Тестирование Flow:**
   * Тест на полную последовательность эмиссий стейта во времени (`Loading -> Success`).
   * Тест на нетривиальное потоковое поведение: отмена устаревших запросов и дебаунс (при быстром изменении ввода запроса поиск отправляется один раз с задержкой 500мс, предотвращая гонку сетевых запросов).
