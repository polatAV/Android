# Финальный проект по Android-разработке: Персонализированный Offline-First Rick & Morty Client

### Выполнил: Полатинский Артем (Группа: ПИКД(2))

---

## Описание проекта
Приложение развито из базового клиента Rick & Morty API в персонализированный offline-first mini-product. Оно предоставляет пользователям возможность локальной работы с профилями, личными заметками к персонажам мультсериала, тегированием героев и фоновым отслеживанием изменений их статуса.

---

## 1. Новые пользовательские данные
* **Локальные профили (`users`)**: Таблица в Room, хранящая профили пользователей (ID, имя, emoji-аватарка). Все пользовательские данные изолированы по `userId`.
* **Заметки (`character_notes`)**: Таблица, связывающая `userId` и `characterId` с текстовым описанием персонажа.
* **Теги (`character_tags`)**: Таблица пользовательских меток, назначенных конкретным героям.
* **История поиска (`search_history`)**: Таблица в Room, хранящая поисковые запросы активного пользователя с временной меткой.
* **Настройки (DataStore)**: Локально сохраняются активный `userId`, тема оформления (светлая/темная/системная) и интервал фоновой синхронизации.

---

## 2. Реализованные сценарии (минимум 3)
1. **Управление локальными профилями пользователей (Сценарий 1 - Существенный по сложности)**
   * Пользователь может создавать профили с выбором аватара из списка emoji и переключаться между ними. При переключении все данные (избранное, история, заметки) мгновенно и реактивно обновляются.
2. **Личные заметки и тегирование персонажей (Сценарий 2 - Личный раздел)**
   * На детальном экране персонажа можно сохранять текстовую заметку и прикреплять теги. Вкладка "Заметки и теги" в Личном кабинете собирает всех персонажей с личными данными.
3. **Настройки темы и фоновое обновление статусов (Сценарий 3 - WorkManager + Настройки)**
   * Экран настроек позволяет сменить тему (светлая, темная, системная) и задать интервал фоновой синхронизации. `SyncWorker` опрашивает API Rick & Morty для избранных персонажей текущего пользователя. При изменении статуса (например, Alive -> Dead) отправляется локальное push-уведомление, клик по которому открывает экран деталей персонажа через Deep Link.

> [!NOTE]
> **Реализация истории поиска (Recent Searches):**
> Вместо создания примитивного отдельного экрана, история поиска интегрирована непосредственно в шапку главного экрана (`ListScreen`) в виде динамической горизонтальной ленты быстрых запросов (по аналогии с Google Maps, Spotify и YouTube). Это технически более сложная задача (требует реактивного слияния потоков результатов поиска, кэша и истории во `ListViewModel`), но она обеспечивает бесшовный UX и мгновенный доступ к повторному поиску.

## 3. Offline-First архитектура
* **Кэширование списков**: При успешном сетевом запросе персонажи сохраняются в Room (`cached_characters`).
* **Офлайн-режим**: При отсутствии сети приложение автоматически переключается на локальный кэш с показом красной плашки "Офлайн-режим (показ локального кэша)" вместо падения с ошибкой.
* **Детальный экран**: Информация о персонаже открывается в офлайне, если он был закэширован или находится в избранном.

---

## 4. Фоновая обработка (WorkManager)
* **`SyncWorker`**: Выполняет периодический опрос API для избранных персонажей активного пользователя.
* **`SyncScheduler`**: Запускает/отменяет воркер при изменении интервала синхронизации в настройках.
* **Надежность**: Интеграция Hilt в WorkManager через `HiltWorkerFactory` обеспечивает корректную инъекцию зависимостей даже при работе приложения в фоне.

---

## 5. Тестирование
* **Интеграционные тесты БД Room (`CharacterDaoIntegrationTest`)**: Проверяют изоляцию избранного по пользователям, операции с заметками/тегами и кэшированием.
* **Unit-тесты ViewModels**:
  * `ListViewModelTest` — поиск, debounce, обработка ошибок, выбор профиля.
  * `FavoritesViewModelTest` — реактивная сборка избранного и коллекции заметок.
  * `DetailViewModelTest` — чтение ID из сохраненного состояния, управление избранным.
  * `MappingTest` — проверка мапперов DTO и Entity.
